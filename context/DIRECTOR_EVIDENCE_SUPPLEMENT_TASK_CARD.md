建卡日期：2026-09-05。负责人：另一台现有 DirectorMind 会话的 Codex。状态：任务卡已创建，尚未启动本卡实施。

上游依据及最终接收方：[导演语法库全量收尾与 Skill 交付](DIRECTOR_GRAMMAR_MAIN_TASK_CARD.md)。本卡负责研究补证，主卡负责正式处置、方法库和运行时整合。

## 1. 为什么要做

用户需要把现有影视拆解成果真正用于导演决策。原有 33 份素材的候选相关镜头已经复核，但 61 条候选仍缺少相同触发条件下的跨作品支持或边界；部分声音方法还需要直接审听和时序、归属证据。

主 Codex 无法仅凭 GitHub 的文字记录补出这些新事实。另一台已完成此前的媒体复核和声音研究，更适合继续独立定位、取得合法可用片段并核对证据。不得把“没有看过补样”当成“方法不成立”。

## 2. 希望看到的结果

用户启动本卡后，补样 Codex 能根据精确缺口自主找作品、定位连续片段、分析真实镜头和必要声音，再把可直接整合的证据推送到共享仓库。主 Codex 读取交接产物后，即可判断哪些方法获得支持、哪些需要改适用范围、哪些有依据被排除，无须用户转抄资料或代做技术定位。

工作范围是上述 15 项、61 条原候选。优先调查前三项：它们关联 39 条候选；实际获取困难时可先推进其他已具备素材的缺口。15 项不是必须新增 15 部电影，也不是每条候选单独找一部电影；一个真实片段可以提供多个问题的证据，但每个声明要分别成立。

每项交付至少包含：gap ID、完整关联 candidate ID 清单、作品及季集、所用版本和连续片段范围、源片与片段时间码对应、完整所选片段的逐镜记录、直接观察、解释、未知、支持／边界判断、它改变的具体导演选择，以及可复现的检查方法。声音声明还必须绑定实际审听的方法、Observation 和对应 Shot；字幕或波形不能替代听觉语义，不假设当前工具天然支持视频或音频理解。

交接位置与职责：

- 在自己的 `codex/` 分支新增唯一 ID 的证据文件，复用 `research/evidence/` 的既有格式和验证器，不覆盖任何已有证据文件。
- 在新建的 `research/supplementation/<gap-id>/` 下保存简明交接记录，列证据位置、候选映射、结论和未解决项；不要建立第二套正式资格状态。
- 一组证据完整即可推送并交接，不必等 15 项全部结束。主 Codex 审查后标明接受、需补字段或需补证；退回时只修相关缺口，复用已认可材料。
- 主 Codex 是正式 Grammar、review、索引和全局状态的唯一整合者。交接中的“建议关闭”必须经其证据验收后才成为正式关闭。

## 3. 这次不做什么

- 不重新制作导演语法库，不修改 Skill、router、validator、schema、正式候选资格或原样例。
- 不扩大成新一轮泛题材搜集，不重新蒸馏完整的原有 33 份素材；只有具体矛盾需要时才定点复核已有片段。
- 不以剧情简介、字幕、教材或模型记忆证明镜头事实；不把相似画面直接当相同戏剧触发条件。
- 不生成原创视频、Prompt、视觉风格包或私有项目分镜，不做部署、发布或 main 合并。
- 不要求用户逐部挑电影、逐条找时间码；只有合法媒体确实不可访问或需要用户独有资源时，汇总具体资源需求。

## 4. 不能碰的内容

- 原有源媒体、不可变证据和另一台正在工作的文件，不删除、覆盖或改写历史。
- 主 Codex 拥有的 `skills/`、`research/grammar/`、`context/STATE.md`、原有样例及全局汇总。本卡只写自己新增的证据和补样交接记录。
- 生产数据、D1、Worker、权限、密钥、支付、购买和订阅。使用已经合法可访问且在现有授权范围内的来源；新增付费资源不得自行购买。
- 原片、音频、剧照、联系表、长对白和敏感信息不得进入公共 Git。媒体分析留在本机；只回收本 Agent 创建且已完成用途的临时资源，不动用户原片。
- 不将检索失败、来源不可用或无法审听写成“反例”或“已关闭”；不为了完成数字制造 Observation。
