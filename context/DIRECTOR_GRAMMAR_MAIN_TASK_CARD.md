# 任务名称：导演语法库全量收尾与 Skill 交付（主任务）

建卡日期：2026-09-05。负责人：本会话主 Codex。状态：任务卡已创建，尚未启动本卡实施。

配套任务：[15 项导演证据缺口补样](DIRECTOR_EVIDENCE_SUPPLEMENT_TASK_CARD.md)。两项并行推进，由本卡负责人承担最终整合和交付责任。

## 1. 为什么要做

用户已经投入真实影视片段拆解，希望把文学剧本交给 Skill 后，得到有依据的机位、人物调度、反应分配、节奏和剪辑方案。

目前已有 33 份素材登记、31 份证据、2,344 个镜头单元、124 条候选和 16 个家族，但大量结果仍停留在研究记录和资格验证中。用户还不能完整调用这些成果做导演决策。现有 7 条成熟规则和首组分镜证明了一部分能力，不代表全量语法已经交付。

## 2. 希望看到的结果

用户提交一份锁定文学剧本，给定画幅、时长和执行媒介后，应得到：观众信息计划、关键导演选择、完整可读分镜、Director IR、原文覆盖表，以及必要的备选拍法。关键选择能解释“解决什么问题、为什么这样拍、何时换方案”，并追到真实来源。

用户按场景问题查阅方法库时，能看到适用条件、必需事实、机位与景别、演员路径、反应优先级、表演端点、切点、声音策略、连续性、执行降级、支持与反例。已获跨作品支持的方法进入成熟推荐；已证画面支持但迁移待验证的方法可参与明确标注的候选比较；未核实事实不能冒充依据。

具体交付：

1. 124 条候选到方法、支持、边界、合并或有依据排除的完整映射；保留原候选 ID，不以另起编号隐藏遗漏。
2. 按 16 个家族组织的可调用导演方法库；复用既有文件与生成工具，相同方法合并呈现，不强行做成 124 张重复卡片。
3. 更新原有 `skills/drama-director-compiler/`，使其从文学剧本识别问题、查找方法并作出具体决定；不把预选规则或镜头答案写进输入。
4. 新剧本的完整调用样例和必要的条件变化对照。相同案例可覆盖多个家族，但每个家族的贡献必须指出具体镜头或真实的改选、限制作用。
5. 接收补样任务的证据，更新正式研究处置和受影响的方法；维护单一当前状态、覆盖清单及最终报告。

启动时读取 `AGENTS.md`、`context/00_START_HERE.md`、`context/STATE.md`、原有编译 Skill 及其引用契约，然后读取 `research/grammar/runtime_integration.review.json`、`candidate_rule_index.json`、`director_grammar_v0.2.json`、首组样例和 `context/DIRECTOR_SKILL_DELIVERY_PLAN.md`。

协作约定：双方从包含两张任务卡的共享分支出发，分别使用自己的 `codex/` 分支。本卡负责人是原有 Skill、Grammar、汇总索引、当前状态和原样例的唯一实现者。补样方只新增自己拥有的证据与交接文件；本卡负责人验收、整合，不让用户反复搬运资料。当前任务卡分支为 `codex/director-grammar-task-cards`。

## 3. 这次不做什么

- 不编写 Seedance/H3 适配器，不生成或发布视频，不制作视觉风格包，不改编小说或改写用户锁定的故事。
- 不继续扩大题材、家族或候选范围来追求“覆盖所有电影”。本轮验收分母是现有 124 条候选、16 个家族；允许补样任务针对现有 15 项缺口补充真实片段。
- 不把所有候选强行晋级为成熟规则，不把测试数量、已登记状态或待补清单当成导演能力完成证据。
- 不重复开发已有验证框架，不为了文档变化反复跑完整测试；仅针对实际变化运行相关检查，正式集成按仓库要求执行必要回归。
- 不把演员围读、观众效果或实际生成成功设为本轮研究拆解的无限延长项；相关未验证内容如实保留。

## 4. 不能碰的内容

- 用户原始视频、音频、既有不可变来源记录和私有剧本，不删除或覆盖。必要的来源纠错通过可追溯的纠错记录处理。
- 生产数据、Cloudflare D1、Worker、账号权限、密钥、支付和任何部署或发布。
- 不把原片、截图、音频、长段版权对白、私有剧本或本机敏感信息提交到公共仓库。
- 不覆盖另一台 Codex 正在编写的新增证据；不直接推送或合并 `main`。本卡交付为可审查的共享分支及交付记录。
- 不降低事实证据要求以凑齐完成数量；不能因为来源找不到就把候选写成“已证伪”。

## 5. 怎样才算完成

- [ ] 用户行为符合预期：仅提供文学剧本和制作约束，即可调用 Skill 得到完整导演方案；至少有未围绕指定规则编写的新剧本验证，无须用户先拆镜头。
- [ ] 124/124 条候选全部有明确、可追溯的研究结论及方法去向；没有未处理条目。支持、边界、合并和排除都有具体依据，排除不能用于掩盖证据不足。
- [ ] 16/16 个家族逐项验收：形成有实际导演作用的方法或有依据的限制、排除；对应到样例的具体镜头选择，不只是写出家族名称。
- [ ] 配套任务覆盖全部 15 项缺口、61 条关联候选；本卡已审查其证据，完成所需方法修订及正式处置。仍有实质缺口时，本卡保持未完成，不把待补改名后计入完成。
- [ ] 三处已知首组问题已修正：折纸同时性、门椅空间布局、AI 执行降级；文学事实保持不变，IR、分镜与方法说明一致。
- [ ] 原有重要功能没有受影响：成熟规则路由、候选隔离、来源覆盖、对白保留、声音证据绑定和确定性渲染通过相关回归；没有证据支持的资格变化不得混入。
- [ ] 有测试、截图或前后对比：保留实际运行的验证结果、完整分镜前后对比、必要的简易空间图和新剧本调用记录。本轮不要求生成影片来充当截图证明。
- [ ] 已说明剩余风险和回退方法：工程结果、导演能力覆盖、证据完整性及人工审美状态分别报告；普通 revert 可撤回本轮独立提交，源媒体不受影响。

“全部完成”指把现有范围研究到明确结论并交付可用方法，不要求 124 条全部成立，也不代表具有未经验证的普适性或观众效果。只剩审美与实际生成效果待验证可以如实交付；仍缺关键来源事实或跨作品研究结论则不能宣称总任务完成。
